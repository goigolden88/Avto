## Модель данных

### Общая часть

`Base` ядра (`shared/core/model.ts`, договор семьи): `id` — ULID, `updatedAt` — ISO 8601, `deleted?` — метка удаления, не вычищается. Даты — `ГГГГ-ММ-ДД`, время — `ЧЧ:ММ`, деньги — число в валюте настройки (Р-17).

### Машины

```ts
type Car = Base & {
  name: string          // «Солярис», «Мамина»
  plate?: string        // госномер
  fuel?: string         // топливо по умолчанию: «95», «92», «ДТ», «газ»
  tank?: number         // объём бака, л — для доли бака в заправке
  archived?: boolean    // продана — из выбора уходит, история остаётся
}
```

Машины заводятся в «Настройках» → «Машины». Удаление машины с записями — метка `deleted` на машине и на каждой её записи (по индексу `carId`): так оно доезжает до других устройств синхронизацией.

**Главная машина** — настройка устройства (Р-21): ключ `mainCar` в `settings` ядра, в базу журнала и в синхронизацию не попадает. Машина новой записи — главная, если она активна; иначе машина последней внесённой записи (по `id`), архивная не подставляется; записей нет — первая заведённая.

### Журнал

Один журнал записей пяти видов вместо четырёх листов Excel (Р-03).

```ts
type EntryKind = 'fuel' | 'wash' | 'repair' | 'fine' | 'other'

type Entry = Base & {
  carId: string
  kind: EntryKind
  date: string
  amount: number        // сколько заплатил; у заправки — одно из трёх чисел (Р-06)
  odometer?: number     // пробег по одометру, км
  note?: string         // «Примечание», «Коммент», «Субъективная причина» Excel

  // fuel
  station?: string      // АЗС: «Лукойл», «Газпром»
  fuel?: string         // по умолчанию — машины
  liters?: number
  price?: number        // цена литра
  consumption?: number  // л/100 км с бортового компьютера, как показал при заправке (Р-05)
  tankBefore?: number   // доля бака до и после, 0…1
  tankAfter?: number

  // repair, other
  what?: string         // «замена колодок», «ОСАГО»
  service?: string      // где делал (repair)

  // fine
  violation?: string
  paid?: boolean
  paidDate?: string
}
```

Заправка: из `liters`, `price`, `amount` вводятся любые два, третье считается **при сохранении** и хранится — чтобы итог не зависел от округления на лету (Р-06). Все три введены и не сходятся больше чем на 1 % — предупредить, сохранить как ввёл.

Журнал — на «Главной». Форма записи показывает поля вида; при сохранении поля чужих видов стираются, а поля, которых в форме нет (`tankBefore`, `tankAfter`), остаются. Отбор — по машине, виду и периоду (месяц, год, всё). Запись, чья машина не найдена, показывается с «машина не найдена».

### Маршруты

Точки и маршруты — справочники, поездки — записи (Р-12…Р-15).

```ts
type Point = Base & {
  name: string          // «Дом», «Работа», «ТЦ Мега»
  city: string
}

type Route = Base & {
  fromId: string        // Point
  toId: string          // Point
  name: string          // «по МКАД», «через центр»
  link?: string         // маршрут в Яндекс Картах
  note?: string
}

type Trip = Base & {
  routeId: string
  carId?: string
  date: string
  start: string         // время выезда
  minutes: number       // в пути
  source: 'timer' | 'manual'
  note?: string         // «мероприятие», «ливень», «авария на въезде»
}
```

Направление важно: «Дом → Работа» и «Работа → Дом» — разные пары. Незаконченный замер («Поехал» без «Приехал») живёт только на устройстве и в базу не пишется; при следующем открытии — спросить: «Приехал в …?» / вписать минуты / выбросить (Р-13).

Маршруты — вкладка «Маршруты» рядом с «Главной» (Р-24, задача 6 Авто-3, #20). Сверху — карточка идущего замера, ниже — маршруты по парам точек с «Поехал» у каждого, под ними — точки (имя, город; город новой — из последней заведённой). Тап по паре — сравнение (`#/routes?from=…&to=…`): маршруты по возрастанию медианы, у каждого — разбивки, «Поехал», ссылка на карту, правка и его поездки. Блоки сворачиваются (`Fold`).

- **Замер** — `{ routeId, startedAt }` (мс) в `settings` устройства под ключом `tripTimer`, как главная машина (Р-21): переживает перезагрузку и на другие устройства не едет. Идёт замер — второго «Поехал» нет, на «Главной» — строка со ссылкой на «Маршруты». «Приехал» — поездка `source: 'timer'`: дата и время выезда — с «Поехал», минуты — до «Приехал», округлённые, не меньше 1; «Вписать минуты» — то же, минуты вводятся; «Выбросить» — ничего не пишется. Дольше 12 часов — карточка говорит, что «Приехал» не нажали, и «Приехал» нет; маршрут или его точка удалены — только «Выбросить»
- **Поездка вручную** — маршрут, дата (сегодня), время выезда, минуты (целое больше нуля), машина, заметка; `source: 'manual'`. Правка отметку не меняет
- **Машина поездки** — `defaultCarId` журнала: главная устройства, иначе машина последней записи (Р-21); можно сменить или убрать; машин нет — поля нет
- **Удаление** — точку, которая стоит в живых маршрутах, не удалить: «сначала удалите маршруты: N». Маршрут — вместе с поездками, метками `deleted`, после вопроса с их числом


```ts
type Prefs = Base & {      // одна запись `prefs:main` — общая для всех устройств
```

Имя `settings` занято ядром: там токен и состояние устройства, и они не синхронизируются никогда (договор ядра, «Устройство и origin»). Общее для всех устройств — в `prefs` (Р-17).

## Что считается, а не хранится (Р-09)

- **Км с прошлой заправки** — разница `odometer` с прошлой заправкой той же машины, у которой одометр есть; прошлая — по дате, в один день — по внесению. Меньше прошлого — «одометр меньше прошлого», а не минус. В строке заправки журнала (Р-23)
- **Рост цены** — `price` к прошлой заправке **того же топлива** (любой машины) с ценой, в % (Р-07); равные до копейки — «без изменений», разница меньше 0,1 % — с сотыми («+0,04 %»), чтобы разные цены не дали «+0 %». Заправка без цены или без топлива «прошлой» не бывает: следующая сравнивается с последней, у которой цена есть. Топливо сравнивается без пробелов по краям и регистра. В строке заправки журнала (Р-23)
- **Цена километра** — по машине и периоду из отбора журнала (месяц, год, всё): деньги журнала за период / пробег за период; отдельно «топливо» (заправки) и «всё» (все виды, штрафы тоже). Пробег — последнее показание одометра в периоде минус последнее до него, а без такого — первое в периоде; показания — у записей любого вида. Рядом — пробег и «по N записям из M» (с одометром из всех записей машины в периоде). Показаний меньше двух или пробег не больше нуля — «мало данных» с тем же основанием (Р-08). При «Все машины» — строкой на машину. Запись с испорченной датой в пробег не идёт (её показание не встаёт ни до периода, ни в него), но при «Всё» входит в счёт «из M». Блок «Итоги» (Р-23)
- **Траты по видам и средний расход** — сумма и число записей по виду за период, плюс итог; виды без записей в периоде не показываются; расход — среднее введённого `consumption` по заправкам периода, «по N заправкам» (Р-05). Блок «Итоги»; вид записи из отбора на итоги не действует — подпись об этом видна, только когда вид выбран (Р-23)
- **АЗС подешевле** — за 6 месяцев до сегодня, по всем машинам, отбору не следует: по каждому топливу АЗС по возрастанию средней цены литра (сумма ÷ литры), с числом заправок; одна АЗС — «сравнить не с чем». Выше — топливо, на котором заправлялись чаще. Названия сравниваются без пробелов по краям и регистра, показаны — как в последней заправке этой АЗС. Блок «Итоги» (Р-23)
- **Где видно в журнале** — сверху отбор (машина, вид, период) отдельным блоком, под ним «Итоги», под ними список: один отбор над обоими
- **Маршруты** — по паре точек: медиана минут по маршруту, разбивка по часу выезда и будни / выходные; рядом — число поездок и доля ручных. Поездки с заметкой показываются, но выделены — по ним видно, почему выброс (Р-14). Медиана при чётном числе — среднее двух средних, до минуты; поездок нет — «поездок нет», а не «0 мин». Час выезда — по `start`: 7:00–7:59 — «7 ч», показаны только часы с поездками. Выходные — суббота и воскресенье, праздники не учитываются. Маршруты пары — по возрастанию медианы, без поездок — в конце. Расчёты — `modules/routes/compare.ts`
- **Парковки** — по месту: доля «сразу / с трудом / мест нет» по часу и дню недели, медиана минут поиска

## Импорт Excel (Р-10)

Путь семьи: «Импорт» → промпт для ИИ с описанием формата → ИИ переводит Excel в JSON `avto-import` → приложение проверяет и показывает, что добавит. Листы Excel → виды записей: Заправки → `fuel`, Автомойка → `wash`, Ремонт → `repair`, Штрафы → `fine`. Машина — выбор при импорте. «Уплачено» → `amount`, «Цена» → `price`, «Объём» → `liters`, «Компания» → `station`, «Тип топлива» → `fuel`, «Пробег» → `odometer`, «Расход…» → `consumption`, «Заполняемость полоски бака до/после» → `tankBefore`/`tankAfter`, «Предмет ремонта» → `what`, «Тип нарушения» → `violation`, «Примечание», «Коммент», «Комментарий», «Субъективная причина» → `note`. «Разница в цене» и «Разница пробегов» не переносятся — приложение посчитает.

Устройство (задача 5 Авто-3, #17). Разделы `avto-import` — виды записей: `fuel`, `wash`, `repair`, `fine`, `other`; поля — имена `Entry`: поля вида из формы, плюс `date`, `note`, у заправки — `tankBefore`/`tankAfter`. Разделы, проверки и описания для промпта — `modules/log/import.ts` (`IMPORT_SPECS`, `planLogImport`), разбор файла и промпт — `importing` ядра из `app/core.ts`. Блок — «Настройки» → «Импорт записей»: `ImportRecords` ядра, над полем — выбор машины (по умолчанию главная устройства, иначе машина последней записи, Р-21; машины из архива — тоже, с пометкой «в архиве»); смена машины сбрасывает разобранное и вставленный текст. Машин нет — блок просит завести машину. Правила разбора:

- без даты или без суммы (у заправки — меньше двух чисел из трёх) — «не разобрано»; третье число считается, как в форме (Р-06); три несходящихся больше `MISMATCH` — как есть, с заметкой
- топлива нет — топливо машины
- доля бака: 0…1 — как есть, больше 1 и до 100 или «25 %» — процент, делится на 100; вне 0…100 — поле отбрасывается с заметкой
- штраф — оплачен, если не сказано `"paid": false`; `paidDate` — только если есть
- испорченное необязательное поле (пробег, расход, дата оплаты) — отбрасывается с заметкой, запись идёт
- «уже есть» — живая запись той же машины с тем же видом, датой и суммой до копейки, в базе или раньше в том же файле: пропускается

## Известные слабые места

- Пробег вводится не всегда — цена километра будет «по N записям из M», а не точной
- Замер поездки на одном устройстве не закончить на другом (Р-13)
- Цена парковки — строкой: сравнить цены нельзя, и пока не нужно
- Импорт: «уже есть» — та же машина, вид, дата и сумма. Две настоящие одинаковые траты в один день (две мойки по 500) — вторая уйдёт в «пропущено»; добавить её — руками
- Импорт: «уже есть» сличает только живые записи — удалённая запись при повторном импорте того же файла вернётся
- Доля бака (`tankBefore`/`tankAfter`) хранится и приходит импортом, но на экране не видна — ни в форме, ни в журнале
