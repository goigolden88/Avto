# Процесс

Обновлён: 16.10.2026

Как ведётся работа над проектом. Не про то, что строим, а про то, как.

## Где что живёт

| Что | Где |
|---|---|
| Код приложения | `github.com/goigolden88/Avto`, публичный; сайт — `goigolden88.github.io/Avto/` (с Авто-3) |

| Конвейер и его правила | `github.com/goigolden88/Shtab` |

## Подмодуль ядра

- **Клон** — `git clone --recurse-submodules`; уже склонированное — `git submodule update --init`
- **`src/shared` отсюда не правится.** Не хватает ядру — сказать человеку и остановиться; правка — сессией `FamilyCore`, решением Я-NN
- **Обновление ядра** — `git submodule update --remote src/shared`, проверки по коду выхода и коммит указателя. Видимое человеку — строка в `src/changes.ts`
- **Перед пушем** — `git status` чистый и в подмодуле тоже
- **В `src/shared` не запускать `npm install`**

## Разделение работы

- **Сессия Штаба** — планирование, документы, задачи конвейеру, решения с владельцем. Правит `docs/` и `CLAUDE.md` своей веткой и PR
- **Конвейер Штаба** — код по задачам: исполнитель берёт issue с `готово`, присылает PR; ревьюер ставит метку; правка `docs/` и `.github/` — только через `нужно-решение`
- **Владелец** — ставит задачи, принимает решения, сливает PR. Ничего не сливается без него

## Поток изменений

1. Задача — issue по шаблону «Задача»; решение владельца, принятое до неё, — блоком «Решение»
2. Исполнитель — ветка, код, тесты, `npm test`, `npm run build`, `npm run smoke`, PR с отчётом
3. CI «Проверки PR» — те же проверки на каждый PR
4. Ревьюер — метка; владелец сливает
5. `main` выкатывается на Pages сам; проверка — на телефоне после автообновления

## Правила ведения документов

- Документы — источник истины; код им подчиняется
- Решение — в `05` в момент выбора, с датой; старое не переписывается, отмена — новой записью
- Журнал — новые записи сверху: сделано, состояние, следующий шаг, «не описано в документах»
- Устаревшее — сказать, не подстраиваться
- Личных данных в документах нет: заголовки Excel — да, строки — нет
